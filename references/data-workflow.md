# 名单、表格与数据流

## 原始材料接收

收集当届规程、代表队报名表、必要的汇总表和上一届模板。云文档要求登录时请用户导出文件，不假装已看见表格，也不复用原分享链接进入公共包。将源文件只读保存，另建解析表和差异报告。

如果先制作Excel，同一工作簿按丙组、丁组分子表，保留用户模板；项目有成绩、排名、得分。原对话要求运动员编号暂空，不能自编真实编号。匿名程序内的技术ID与正式运动员编号不同。

逐队核对组别、代表队、性别、选手、项目与接力报名。代表队可能由专业或年级组合组成，不能一律当行政班拆分。缺参赛队先确认保留空队、排除还是补表；曾排除某届年级是当届决定，不成为通用排除规则。

## 多来源核对

同时提供逐条差异和来源：仅原报名表有、仅新汇总表有、疑似同人异字、组别/性别/项目不一致。新汇总表有而旧报名表无，意味着来源有差异，不是程序凭空生人。缺代表队、性别、项目时不能仅凭姓名补录；疑似错别字也必须确认。

核对人数只是第一层，还要核对每人每项报名及重复项。同姓名跨代表队不能自动合并。表格男女组未填时，不能凭名字判断；若按行序映射，须得到用户确认并记录依据。

## 示例数据结构

`assets/starter/seed.json` 是已经生成的演示结构，只有虚构编号。顶层：

```json
{
  "teams": [{"name": "示例代表队A", "group": "丙组"}],
  "events": [{
    "id": "丙组-男子-100", "group": "丙组", "sex": "男子",
    "key": "100", "name": "100米决赛", "type": "track",
    "preliminary": false, "relay": false,
    "entries": [{"id": "demo-001", "team": "示例代表队A", "name": "选手001"}]
  }]
}
```

`logic.mjs` 的 `makeSeed()` 可由队伍结构生成项目。当前项目代码见其 `DEFINITIONS`，不要猜测代码。真实导入器应报告未知代码而非静默丢弃。

同一运动员在不同个人项目中应沿用稳定ID；跨组ID需区分。修改报名后不能让原ID指向另一人，否则历史成绩会错配。示例生成器以队伍和人员下标构造ID，只适合固定名单演示；生产导入应建立稳定ID映射，不能随排序变化重编号。

## 保存、备份和恢复

- `seed.json`：比赛名单和项目；正式使用含个人信息，不能公开。
- `data/results.json`：成绩、确认和评奖选择。
- `data/audit.ndjson`：逐次修改记录；含记录员信息，不公开。
- `data/access.json` 与 `*links*.txt`：本机访问密钥/链接，不公开。

比赛前和关键节点导出CSV及JSON，并复制一份到另一受控位置；CSV是复核材料，不等于完整可恢复数据库。API备份JSON含 `seed` 与 `state`，不含访问密钥；应以私密资料保管。

恢复前停止计分服务，保存当前目录副本。在独立恢复目录将备份的 `seed` 写入 `seed.json`、`state` 写入 `data/results.json`，启动后验证人数、成绩、确认、总分和权限。旧访问密钥如需保留，只能在私密受控恢复流程中单独迁移，不能放公共包。比赛中不要边服务边替换文件；不要让两进程同时写同一个data目录。
