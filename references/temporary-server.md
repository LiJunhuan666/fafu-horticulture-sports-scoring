# 让电脑作为临时服务器

## 选择访问方式

| 方式 | 适用 | 启动与网络 |
|---|---|---|
| 本机 | 演练、单人计分 | 默认127.0.0.1，只能当前电脑 |
| 局域网 | 同一Wi-Fi记录员 | 0.0.0.0监听，其他设备访问电脑局域网IP |
| 临时公网 | 手机移动网络、异地 | 本机服务加Cloudflare临时隧道 |
| 持续在线服务器 | 电脑关机仍需访问 | 迁移到始终在线主机，另行部署 |

“服务器”是一种提供服务的角色，普通电脑也能承担。临时隧道只转发流量，不把程序或数据变成云托管。电脑关机、休眠、断网、程序退出或隧道中断时，外网入口不可用。网址失效不等于本地成绩丢失。

## 1. 本机启动

复制匿名示例到独立工作目录，进入副本，在PowerShell运行：

```powershell
node --version
powershell -NoProfile -File .\StartScoreboard.ps1 -Mode Local -Port 8787
```

Node.js要求20+，通过PATH查找，不写某台电脑的绝对安装路径。启动窗口保持打开；Ctrl+C停止。端口已用时先确认是已有比赛服务还是其他程序，不能直接结束未知进程；演练可改 `-Port 18787`。

首次启动自动生成 `data/access.json`，`data/private-links.txt` 保存本机录入和只读入口。控制台不打印口令；该文件是私密运行产物。主页能打开但提示输入口令是正常的，不代表服务没启动。

脚本不申请管理员、不自动修改防火墙、启动项或电源设置。若提示系统禁止脚本执行，在设备管理规则允许且已审阅脚本的前提下，可仅为这次启动使用 `powershell -NoProfile -ExecutionPolicy Bypass -File .\StartScoreboard.ps1`（不改变系统持久策略）。受管理设备不应绕过组织策略，可联系管理员。也可手动设置环境后运行：

```powershell
$env:HOST = '127.0.0.1'
$env:PORT = '8787'
node .\server.mjs
```

## 2. 同一Wi-Fi访问

停止自己的本机演练进程后重启：

```powershell
powershell -NoProfile -File .\StartScoreboard.ps1 -Mode LAN -Port 8787
ipconfig
```

从实际联网网卡找到IPv4（排除虚拟网卡和127.0.0.1）。假设是 `192.168.1.50`，在另一设备打开 `http://192.168.1.50:8787/`。0.0.0.0只是监听配置，不能当网址。

如需要，仅允许选定端口在“专用网络”入站；不要关闭整个防火墙。公共校园Wi-Fi可能隔离客户端，同一Wi-Fi也未必互通；可换受控热点，或选择临时公网。示例LAN是HTTP，链路上的人可能观察数据和口令，仅限可信网络，必要时改HTTPS或受控隧道。

在**另一个终端**生成该地址的角色链接：

```powershell
node .\WriteLinks.mjs --base http://192.168.1.50:8787
```

读取 `data/share-links.txt`，只给记录员录入入口；普通查看者只给查看入口。不要把private-links中的localhost网址发给手机。

## 3. 临时公网

先确认需要外网访问及允许分享哪些数据，再从Cloudflare官方渠道安装cloudflared（本包不含二进制、不含账号）。保持Local模式应用运行，另开终端：

```powershell
cloudflared tunnel --url http://127.0.0.1:8787 --no-autoupdate
```

如连接失败，可按网络情况尝试历史排错参数，不能保证所有网络适用：

```powershell
cloudflared tunnel --url http://127.0.0.1:8787 --no-autoupdate --protocol http2 --edge-ip-version 4
```

等待工具输出实际HTTPS临时域名。不要硬编码旧域名或把它放公开技能中。第三个终端用获得的实际地址生成入口：

```powershell
node .\WriteLinks.mjs --base https://YOUR-TEMP-HOST.trycloudflare.com
```

将命令中的示意域名替换为当前真实域名。脚本只写本机 `data/share-links.txt`，不上传也不打印口令。使用页面“分享”亦可，但须在正确的公网域名页面里生成；本机页面生成的localhost链接不能外发。

Quick Tunnel临时域名可能重启就变化，且没有长期可用保证。命名隧道+自有域名可固定地址，但仍依赖本机在线。不要把固定域名当作持续托管。

## 4. 开赛前验证和运行

本机页面与API → 同一Wi-Fi另一设备（如使用LAN） → 外网手机移动数据 → 只读和录入权限 → 一条虚构成绩同步与导出。仅首页200不够，至少验证无口令401、只读写403、只读不取得录入口令。验证成绩不能写入现场库。

接电、保持网络、按用户同意的当天设置避免自动休眠，记录原设置便于赛后恢复；不要默认永久禁用休眠。不同设备实际打开并复制链接一次，确认微信/QQ没有截断口令。固定备用本机/LAN入口，准备Excel或纸质记录。

## 5. 重启、固定入口和赛后

关机后数据保留；再开机需重启应用及隧道，重新检查地址并分发新入口。旧标签不会自动变成新域名。若做桌面快捷入口，让它读取最新私密链接文件，不把临时域名硬编码；通过系统KnownFolder获取桌面，不假设个人路径。

自动登录启动/唤醒任务属于可选配置，须用户明确需要，记录创建项并提供撤销方式；唤醒后还要检查隧道是否需要重连。本包不创建这些任务。

赛后导出受控备份，Ctrl+C停止本人启动的隧道与服务。若口令已发给不该访问的人，停服、私下备份并轮换两个密钥，清理旧分享文件后重启；原标签可能残留sessionStorage，需使用新入口。不能仅隐藏按钮当作撤权。
